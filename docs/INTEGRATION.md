# EduBridge + finalIL integration

## Current architecture

- **Frontend source:** `giii5121/EduBridge` (React 19 + Vite + React Router).
- **Diagnostic engine:** `0xfrq/finalIL` P-DINA implementation, vendored under `backend/cdacdm`.
- **Inference checkpoint:** EEDI P-DINA checkpoint copied to `backend/artifacts/model`.
- **API:** FastAPI adapter in `backend/api_server.py`.
- **Deployment:** Docker Compose; API listens on port 8000 inside the container.

The original repositories are left unchanged. The EduBridge React application is linked at `frontend/` as a Git submodule pinned to a known upstream commit; the finalIL runtime and checkpoint are vendored under `backend/` so the API can be deployed from this private repository.

Clone the project with `git clone --recurse-submodules https://github.com/Rubbra-f/EduBridge-Private.git`, or run `git submodule update --init --recursive` after a normal clone.

## API

- `GET /health` — unauthenticated readiness check; reports whether the checkpoint files are present.
- `GET /api/v1/model` — authenticated model metadata and diagnosis policy.
- `GET /api/v1/assessment/fixed` — authenticated EEDI-only allowlisted form metadata; returns no answer keys and explicitly indicates whether question content is available.
- `POST /api/v1/diagnose` — authenticated P-DINA diagnosis for one student.
- `POST /api/v1/assessment/submit` — trusted server-to-server submission of EEDI answer choices (1–4); scores choices against the private answer key before P-DINA inference. The response includes aggregate `correct_count`, `incorrect_count`, `incorrect_question_ids`, and `score`; it never returns the correct option values.
- `POST /api/v1/narrative` — authenticated P-DINA diagnosis plus Indonesian explanation generated by Google Gemini.

Example diagnosis payload:

```json
{
  "student_id": "student-123",
  "responses": [
    {"question_id": 137, "response": 1},
    {"question_id": 82, "response": 0},
    {"question_id": 90, "response": 1}
  ]
}
```

Responses are binary: `1` correct, `0` incorrect, and `null` unanswered. Question IDs must belong to the packaged P-DINA-supported EEDI fixed form; duplicate and unsupported IDs are rejected. The API key is supplied using the `X-API-Key` header.

## Run the API

From the repository root:

1. Copy `.env.example` to `.env`.
2. Set a long random `EDUBRIDGE_API_KEY` and a Google AI Studio `GEMINI_API_KEY`.
3. Set `EDUBRIDGE_CORS_ORIGINS` only to trusted origins if browser access is ever enabled. Do not put the API key in a Vite `VITE_*` variable or ship it to the browser.
4. Run `docker compose up --build -d`.
5. Check `curl http://127.0.0.1:8000/health`.

The compose file binds the API to loopback on the VPS. Put a trusted reverse proxy / server-side EduBridge backend in front of it. The browser must never receive either API key. Gemini receives compact, pseudonymized diagnostic facts; raw answers and student IDs are not sent to Google. Review Google's API data terms and your institution's student-data policy before using real student records. A deterministic template is used if Gemini is unavailable or its output fails validation.

## Gemini narrative provider

The optional narrative layer uses Google's OpenAI-compatible Gemini endpoint (`https://generativelanguage.googleapis.com/v1beta/openai/`) with `gemini-2.5-flash`. P-DINA remains the diagnostic model; Gemini only phrases computed results and cannot change mastery estimates, gaps, or intervention decisions. Free-tier quotas vary by model and project; check Google AI Studio for current limits.

## EEDI-only assessment boundary

The diagnostic assessment is now **EEDI-only**. The current packaged fixed_form.csv is the allowlist: only its original EEDI QuestionId values, after validation against the P-DINA checkpoint and the target/reliability flags, are accepted by both /api/v1/diagnose and /api/v1/narrative. Duplicate IDs and IDs outside this fixed form are rejected. EduBridge local quiz IDs and responses must not be submitted to the diagnostic engine.

GET /api/v1/assessment/fixed returns safe metadata for this allowlisted form, including original EEDI IDs and concept labels. Correct answers, training response counts, and answer-key fields are never returned.

The browser must submit selected option values (1–4) only to a trusted EduBridge server-side layer. That server calls `/api/v1/assessment/submit` with `X-API-Key`; the diagnostic service compares each choice against its private `item_bank.csv` answer key and converts it to the binary correctness signal expected by P-DINA. Never accept a browser-supplied `IsCorrect` value as authoritative. The `/api/v1/assessment/submit` endpoint itself is authenticated with the private API key and must not be called directly from browser JavaScript.

**Student delivery is not enabled yet.** The private repository currently packages model/item metadata and image paths, but not the actual EEDI question statements or image bytes. The endpoint therefore reports question_content_available=false and delivery_status=metadata_only. Before showing these questions to students, add the authorized EEDI question-content and image package, preserve the exact original option order, and keep correct answers exclusively server-side. Do not substitute invented or locally-authored question text. Confirm Eedi data and image redistribution terms before packaging content in a deployed service.

## Model scope and limitations

- The checkpoint was trained on EEDI NeurIPS 2020 Task 3/4 data, not on EduBridge's local quiz data.
- The training population is primarily UK lower-secondary learners; it is not a validated representative sample of Indonesian SMA learners.
- The current target map contains 11 algebra-related concepts. Do not assume it diagnoses all EduBridge topics (geometry, statistics, probability, or calculus).
- Mastery probabilities are model estimates, not verified ground truth. A low-evidence result must be treated as insufficient evidence, not a learning gap.
- Intervention entries marked as placeholders require teacher/lecturer validation. The model does not estimate intervention effectiveness.
- The `artifacts_calculus` checkpoint in finalIL is synthetic demo data and is intentionally not packaged as a real student model.

2. Add a server-side EduBridge application layer with real authentication, per-user authorization, session persistence, and database storage. The current frontend demo login is not a production identity system.
3. Connect quiz submission to the server-side layer; keep answer keys and API credentials off the client.
4. Add integration tests using known QuestionIds, invalid IDs, empty responses, and low-evidence students.

## Provenance

The backend package and EEDI model artifacts are adapted from `https://github.com/0xfrq/finalIL`. The frontend source of truth is `https://github.com/giii5121/EduBridge`. Review each upstream repository's license and data terms before redistributing or deploying any additional source, question content, or assets.

### EEDI question-content and image restriction

The NeurIPS 2020 Task 3/4 package supplies question content as image files rather than text fields. The challenge paper states that these images were shared solely for the competition and must not be used for other purposes. Therefore this repository does not copy, publish, or serve those image files as EduBridge website content. The assessment UI must remain disabled until Eedi grants explicit permission for the intended educational website use or provides a separately licensed content feed. See the [Eedi challenge page](https://www.eedischool.com/projects/neurips-education-challenge) and the [challenge paper](https://simon.peytonjones.org/assets/pdfs/diagnostic-questions.pdf).

### Authorized EEDI content-pack format

No EEDI question text or image files are included in this repository. If you obtain written permission to use the content in EduBridge, mount `backend/content/eedi_questions.json` into the API container. The loader requires `license_confirmed: true`, a non-empty `authorization_reference`, and exactly one entry for every supported fixed-form QuestionId. Each entry must contain the original prompt and four options with stable values 1–4 in the original option order. The API rejects incomplete, duplicate, unsupported, or malformed entries. Do not put the correct answer in this file; the answer key remains in the private server-side model artifact. The compose file mounts this directory read-only. Without a complete authorized pack, the endpoint stays in `metadata_only` mode.

Example structure only (not question content):

```json
{
  "license_confirmed": true,
  "authorization_reference": "REPLACE_WITH_WRITTEN_PERMISSION_REFERENCE",
  "questions": [
    {
      "question_id": 137,
      "prompt": "AUTHORIZED ORIGINAL QUESTION TEXT",
      "options": [
        {"value": 1, "text": "ORIGINAL OPTION 1"},
        {"value": 2, "text": "ORIGINAL OPTION 2"},
        {"value": 3, "text": "ORIGINAL OPTION 3"},
        {"value": 4, "text": "ORIGINAL OPTION 4"}
      ]
    }
  ]
}
```
